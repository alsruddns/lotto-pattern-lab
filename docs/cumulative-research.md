# 누적 연구 구현 현황

## 기존 기능 확인 (2026-10-21)

| 항목 | 상태 | 확인된 동작과 한계 |
| --- | --- | --- |
| 수학 공식 라이브러리 | 이미 구현됨 | SQLite `patterns`, `observations`, `pattern_events`에 공식·평가·이벤트를 저장하고 canonical fingerprint로 중복을 막는다. |
| 후보 평가와 선택 | 이미 구현됨 | GP 후보는 학습·검증 점수, 활성 비율, 복잡도, 점수 간격을 사용한다. 독립 테스트 점수는 Elite 선정 점수에서 제외된다. |
| 수식 계보 | 이미 구현됨 | GP의 Elite 복원과 세대 연산에서 원본 ID를 전달하고 등록 때 `pattern_lineage`에 부모-자식 관계를 기록한다. 단순 유사도와 실제 계보는 별도다. |
| GP Elite Seeding | 이미 실행에 연결됨 | 연구 시작 시 호환 패턴을 선정하고 체크포인트에 고정한 뒤 `ResearchRunContext`로 전달한다. 초기 개체군의 설정 비율만 복원하고 나머지는 무작위 개체로 채운다. |
| 특징·AST 호환성 | 이미 구현됨 | 특징 이름 재매핑, primitive set 버전, 출력 개수, AST 허용 목록, 깊이와 노드 수를 검사한다. |
| 중복 및 계열 제한 | 이미 구현됨 | canonical fingerprint, origin별 상한, 모델별 상한으로 Elite 후보 중복을 줄인다. |
| 고적중 후보 재검증 | 이미 구현됨 | 독립 GP 실행 결과 중 임계 후보를 재검증 작업 큐에 등록하고 중복 작업을 걸러낸다. |
| 시간별 성능·데이터 분할 | 이미 구현됨 | 시간 순서형 train/validation/independent test 결과와 별도 무작위 대조군이 저장된다. 테스트 구간은 후보 선택과 Optuna 목적 함수에 쓰지 않는다. |
| Optuna 설정 적용 | 이미 구현됨 | 사용자가 선택한 완료 GP Study의 설정을 엔진·프로파일·데이터 범위와 대조하고 입력에 명시적으로 반영한다. 현재 저장된 Study에 전체 데이터 해시가 없는 경우도 있어 그 기록은 강한 호환 판정에 부족하다. |
| 적응형 GP 설정 추천 | 미구현 | Optuna 적용은 사용자가 선택한 기존 Trial 반영이며, 새 연구 호환성을 검증한 추천 기능은 없다. |
| PySR 교차 연구 재사용 | 구현 범위 제한 | PySR의 `guesses`는 설정에서 직접 지정할 수 있고 `from_file` 재개는 같은 실행 디렉터리의 중단 복구용이다. 다른 연구의 Hall of Fame을 자동 주입하는 흐름은 없다. 현재 `.venv`에는 PySR 2.7.2가 있으나 Julia 실행 파일이 없어 실제 PySR 연구 가능 상태가 아니다. |
| 성장 분석 | 부분 구현 | 회차별 결과, 패턴 등록 수, 계보 수, validation·independent-test 요약과 2회차 비교가 있다. 누적 성장 지표와 모드별 다중 시드 비교는 아직 없다. |
| 미래 독립 검증 | 이미 구현됨 | 사전 고정한 추천을 추첨 후 대조하는 별도 기록이 있다. 과거 구간 재평가는 미래 예측력의 증거로 취급하지 않는다. |

## 이번 변경의 원칙

- 이전 실행의 체크포인트와 결과는 소급 수정하지 않는다. 신규 실행에만 연구 모드, 데이터 해시, 설정 출처를 기록한다.
- 누적 모드의 Elite 수식은 validation 근거, 특징·엔진 호환성, 시계열 및 데이터 스냅샷 조건을 통과한 경우만 사용한다.
- 독립 탐색은 Elite 주입 없이 기존 무작위 초기화 경로를 사용한다.
- PySR에는 이전 GP AST를 억지로 주입하지 않는다. 설치된 Julia 런타임과 API가 확인되지 않으면 교차 연구 warm start를 제공하지 않는다.
- Optuna 추천은 평가 데이터 해시가 검증되는 경우에만 표시하며, 사용자 선택 전에는 입력 설정을 바꾸지 않는다.
- 누적 횟수·탐색량·검증 점수·독립 테스트 점수를 각각 구분한다. 단일 연구나 단일 시드로 우수성을 단정하지 않는다.
